# Платформа ФСП РД

Сайт Федерации спортивного программирования Республики Дагестан: соревнования, заявки, результаты и рейтинг спортсменов, в котором объяснён каждый балл.

## Запуск

Нужен **Node.js 22.13 или новее**. Проверить: `node -v`. Если версия старше, поставьте LTS с [nodejs.org](https://nodejs.org) или командой `brew install node`.

```bash
cd ~/Downloads/Hack2026/fsp-platform
npm start
```

`npm install` не нужен: у проекта нет внешних зависимостей. Сервер, база (встроенный SQLite), пароли и тесты работают на стандартной библиотеке Node.js.

Логотип ФСП взят из брендбука Федерации спортивного программирования России (fsp-russia.ru/press/brandbook). Шрифт Golos Text подгружается с Google Fonts. Без интернета сайт работает так же, только с системным шрифтом.

## Первый запуск

1. При первом запуске база создаётся сама. В неё попадают только справочники: пять дисциплин вида спорта, уровни соревнований с базовыми баллами, разряды и звания с бонусами, все городские округа и районы Дагестана, параметры рейтинга.
2. В консоли появится одноразовая ссылка вида `http://localhost:3000/setup?token=…`. Откройте её и создайте аккаунт организатора. Ссылку знает только тот, кто запустил сервер. После создания аккаунта она перестаёт работать.
3. На панели организатора есть чек-лист «Первые шаги»: указать контакты Федерации, добавить образовательные организации (без них спортсмены не заполнят профиль), создать первое соревнование, опубликовать документы и первую новость.
4. Название, текст «О федерации», адрес, телефон, почту, Telegram и ВКонтакте организатор заполняет в разделе «Настройки сайта». Заполненные поля появляются в подвале и на странице «О федерации», пустые не показываются.

Спортсмены регистрируются сами на странице «Регистрация».

Настройки через переменные окружения:

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `PORT` | `3000` | Порт сервера |
| `HOST` | `::` | `127.0.0.1`, чтобы сайт был доступен только с этого компьютера |

Резервная копия: остановите сервер и скопируйте файл базы (`data/fsp.sqlite`).

## Кейс №2: проведение соревнований на платформе

Соревнование можно провести прямо на сайте: организатор создаёт контест, добавляет задания и запускает его, спортсмен отправляет решения, организатор проверяет, таблица результатов строится сама, а итог попадает в профиль и рейтинг.

**Как устроено.** Контест — это обычное соревнование первого этапа с галочкой «Проводится на платформе». Поэтому он использует всё, что уже было: статусы (черновик → опубликовано → идёт → завершено → итоги опубликованы), заявки, публикацию итогов, профиль, историю выступлений, рейтинг и уведомления. Модуль добавил три таблицы и не изменил ни одной существующей:

| Таблица | Что хранит |
|---|---|
| `contests` | Время начала и окончания, правила, автосмена статуса по времени, внешняя площадка и ссылка |
| `contest_tasks` | Задания: название, условие, максимум баллов, ссылка на материалы |
| `submissions` | Решения: текст и/или ссылка, время, оценка, комментарий, кто и когда проверил. Каждая попытка хранится отдельно |

**Правила таблицы.** Балл за задание — лучшая оценка среди проверенных попыток, итог — сумма. При равной сумме выше тот, кто раньше отправил последнее решение, принёсшее баллы. Если совпадает и это время, место делится: 1, 2, 2, 4.

**Связь с рейтингом.** При публикации итогов таблица записывается в результаты дисциплины, дальше срабатывает конвейер первого этапа: пересчёт рейтинга, запись в историю изменений, уведомления участникам. Опубликовать итоги с непроверенными решениями нельзя.

**Статусы.** Меняются кнопками в кабинете организатора. Если включить «Менять статус автоматически по времени», опубликованный контест начнётся и завершится сам.

Код модуля: `src/modules/contests.js` (логика), `src/web/pages/contests.js` (страницы), тест сценария защиты: `tests/contest.test.js`.

### Сценарий показа

Подготовка: `npm run sample`, затем `npm run dev`. На странице «Войти» появятся кнопки быстрого входа в пример наполнения (пароль у всех `example123`). В примере уже идёт «Тестовый контест по алгоритмическому программированию»: три задания, шесть участников, проверенные решения и три решения, ждущие проверки.

1. **Первый этап коротко.** Главная → Рейтинг → профиль лидера: разбор, из чего сложился рейтинг.
2. **Организатор создаёт контест.** Войти → «Организатор» → Управление → Создать соревнование: одна дисциплина, формат «Дистанционно», галочка «Проводится на платформе», время и правила → «Создать черновик». Откроются «Задания»: добавить три задания → «Опубликовать» → «Начать соревнование».
3. **Спортсмен участвует.** Выйти → Войти → «Спортсмен» (Сабина Юсупова) → Соревнования → «Тестовый контест…» (или только что созданный: «Участвовать»). Задания, таймер, «Отправить решение». Попытка появится со статусом «На проверке».
4. **Организатор проверяет.** Выйти → Войти → «Организатор» → Панель: «Решения ждут проверки» → «Проверить» → выставить баллы → «Сохранить оценку». Таблица справа обновится.
5. **Итоги.** «Завершить» → проверить оставшиеся решения → «Опубликовать итоги».
6. **Результат в профиле.** Страница контеста: итоговая таблица с баллами по заданиям и колонкой «В рейтинг». Профиль спортсмена: новый старт в истории и в разборе рейтинга, в кабинете уведомление с изменением рейтинга.

## Как считается рейтинг

```
R = сумма 5 лучших P за 24 месяца + Q
P = B × Kм × KN × Kt
```

- **B**: базовые баллы уровня соревнования (Чемпионат или Кубок России 1000, другие всероссийские 600, межрегиональные 400, Чемпионат или Кубок РД 300, другие региональные 150, муниципальные и школьные 60).
- **Kм**: коэффициент места, от 1 за победу до 0,1 за последнее место: `1 − 0,9 × √((место − 1) / N)`.
- **KN**: коэффициент масштаба, победа среди 50 участников весит больше, чем среди 5: `min(1; 0,6 + 0,4 × ln N / ln 50)`.
- **Kt**: давность, первые 12 месяцев полный вес, затем линейно до нуля к 24 месяцам.
- **Q**: бонус за подтверждённый действующий разряд или звание (от 10 за III юношеский до 450 за МСМК).

Все числа хранятся в базе и меняются организатором в «Справочниках и весах». Страница «Методика» (`/rating/method`) показывает текущие значения с примерами.

## Что есть на сайте

**Публичная часть:** главная, соревнования (предстоящие, текущие, завершённые, фильтры по дисциплине и уровню), карточка соревнования с итогами и участниками, общий рейтинг и рейтинги по пяти дисциплинам с фильтром по муниципалитету и поиском, профиль спортсмена с разбором рейтинга и сводкой, методика, календарь сезона, новости, документы (положения, правила вида спорта, материалы), страница о платформе.

**Кабинет спортсмена:** рейтинг и последнее изменение, заявки по этапам, уведомления, профиль (ФИО, дата рождения, населённый пункт, организация, дисциплины, видимость профиля), заявка на разряд с номером приказа.

**Кабинет организатора:** панель «Что требует внимания» и чек-лист запуска, соревнования (создание, редактирование, статусы: черновик → опубликовано → идёт → завершено → итоги опубликованы, отмена), участники с допуском и выгрузкой в CSV, ввод результатов с предпросмотром баллов и расстановкой мест, публикация итогов с пересчётом рейтинга и уведомлениями, спортсмены без аккаунта (для протоколов внешних стартов), проверка и присвоение разрядов, справочники и веса формулы, новости и документы, выгрузка рейтинга в CSV, журнал действий.

**API только для чтения** (`/api/v1`): соревнования, карточка с итогами, рейтинг по дисциплинам, публичный профиль с разбором. Подходит для сайта школы, Telegram-бота или мобильного приложения.

## Безопасность и данные

- Пароли хранятся как хеш scrypt с солью, сессии в cookie HttpOnly, в базе лежит только хеш токена.
- Каждая форма защищена токеном от подделки запросов (CSRF), роли проверяются на сервере.
- При регистрации спортсмен даёт согласие на обработку персональных данных, за несовершеннолетнего согласие даёт законный представитель.
- Спортсмен может скрыть профиль: в рейтинге и итогах вместо имени будет «Профиль скрыт».
- Первый аккаунт организатора создаётся по одноразовой ссылке из консоли сервера.
- Действия организатора записываются в журнал.

## Как расширять

Слои разделены: предметная логика в `src/modules` не знает про HTTP, страницы в `src/web/pages` не пишут SQL напрямую. Новый раздел добавляется так:

1. Таблицы: дописать в `src/db/schema.sql` (`CREATE TABLE IF NOT EXISTS`), справочные значения добавить в `seedBase`, примеры в `seedSample` (`src/db/seed.js`).
2. Логика: новый файл в `src/modules`.
3. Страницы: обработчики в `src/web/pages`, одна строка на каждую в `src/routes.js`, пункт меню в `src/web/layout.js`.
4. Тест: сценарий в `tests/`.

Что уже заложено: новые дисциплины и уровни добавляются через справочники без правки кода, внешние старты учитываются с числом участников по протоколу, у методики рейтинга есть номер версии, открытый API готов для интеграций. Командные соревнования потребуют отдельной таблицы команд поверх заявок.

## Ограничения

- Одна роль организатора на всю Федерацию, без разделения по дисциплинам.
- Документы хранятся ссылками, загрузки файлов нет.
- Письма и SMS не отправляются: уведомления приходят в кабинет.
- Рейтинг внутренний и не заменяет разряды, нормативы ЕВСК и решения спортивных органов.
